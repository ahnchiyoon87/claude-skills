# 하루 업무 보고 — HTML 한 장

받는 사람은 팀장 · 관리자다. 오늘 한 일, 진행 중인 일, 남은 일정을 한 화면에서 읽게 한다. 꼴은 `assets/틀.html`이 정본이고, 사용자가 실물을 보고 고른 꼴이다(사용자 2026-11-17 「이 형식 skill화 … 딱 좋음」).

## 입력
- 사용자가 말로 불러 준 항목이 내용의 정본이다. 빠르게 친 말(오타 · 줄임 · 「~~」 · 「등등」)은 보고서 문장으로 다듬되, 사용자가 말하지 않은 업무 · 수치 · 일정 · 사람은 더하지 않는다.
- 사용자가 다시 불러 주면 같은 날 파일을 고친다. 바뀐 칸만 고치고 앞 칸은 그대로 둔다. 「~도 보고서에 추가」는 칸을 더한다.
- 이 세션에서 확인한 사실과 사용자의 말이 어긋나면(보고에는 「완료」인데 실제로는 아직 도는 중) 보고서를 몰래 고치지 않는다. 보고서는 사용자가 보고하는 시점의 글이므로, 어긋남은 채팅에 한 줄로 알리고 사용자가 정하게 한다.

## 짜임(이 차례)
1. **머리** — 날짜 `YYYY. MM. DD (요일)`(요일은 달력으로 계산해 맞춘다), 제목 「업무 보고」, 소속이나 일 이름 한 줄.
2. **진행 띠** — 차례가 있는 일(회차 · 단계 · 차수)이 있을 때만 둔다. 칸마다 이름과 상태 표시 하나.
3. **오늘 한 일 · 진행 상황** — 항목마다 카드 하나. 카드에는 제목(무슨 일인지 바로 알게), 상태 표시, 개조식 2~3줄을 둔다. 흐름 칩(`A → B → C`)은 실제로 차례가 있는 일에만, 쪽 메모(용도 · 대상 한 줄)는 있을 때만 단다.
4. **방침 · 운영 계획** — 「어떻게 진행할 것인가」처럼 한 일이 아닌 계획은 따로 절을 두고 상태 표시를 「운영 계획」으로 한다.
5. **오후 · 남은 일정** — 왼쪽 선을 강조한 블록 하나.

상태 표시는 넷만 쓴다. 완료(초록), 진행 중 · 마무리 단계(주황), 준비 중(회색), 예정 · 계획(파랑)이다. 표시의 글은 사용자가 말한 상태 그대로 쓴다(「마무리 단계」 · 「제작 중」).

## 문장
- 개조식으로, 「~함 · ~예정 · ~중」으로 끝맺고, 한 줄에 한 가지만 쓴다.
- 받는 사람이 알 필요 없는 내부 사정(도구 이름, 파일 경로, 커밋, 크레딧, 검사 수치)은 넣지 않는다.
- 어제와 오늘이 어떻게 다른지 말했으면(「어제는 착수, 오늘은 검토 · 견적 · 확정 뒤 제작」) 그 차이를 한 줄과 흐름 칩으로 보인다.

## 만들기
- `assets/틀.html`을 복사해 칸을 채운다. 색 토큰, 글꼴, 상태 표시, 카드 꼴은 바꾸지 않고, 쓰지 않는 칸(진행 띠, 방침 절, 흐름, 쪽 메모)은 통째로 지운다.
- 저장은 사용자가 정한 자리, 없으면 세션 임시 폴더에 `업무보고_MMDD.html` 하나로 한다. 같은 날은 그 파일을 고친다. 임시 폴더에 두었으면 「보관하려면 옮겨 두세요」를 한 줄로 알린다.
- 보내기 전에 렌더를 한 번 보고(글 넘침, 좁은 화면, 어두운 화면), 파일을 화면에 띄워 보낸다(Claude Code는 `SendUserFile`의 render). 웹 게시(Artifact)는 사용자가 원할 때만 한다(2026-11-17 게시를 거절했다).
- 채팅에는 바뀐 칸만 짧게 알린다.

## 다른 스킬로
프롬프트 원문 ↔ 한 일 ↔ 판정을 맞대는 작업보고는 work-report, 하루일과 계획과 요청문은 task-prompt, 월간 연구노트는 research-note.
