# 근거 기반 연구노트

연구노트는 수행한 연구의 기록이다. 작업보고를 날짜순으로 붙인 문서나 성과 홍보문이 아니다.
다른 제작·구현 요청을 연구노트 작성으로 바꾸지 않는다. 채팅 초안만 요청하면 요청한 분량의 초안만 내고 절차 설명·자기검수 보고를 덧붙이지 않는다.

## 대상과 양식

- 연구 기간(작성 월)·포함 프로젝트·대상 문서·사용자가 인정한 이전 작성 예시를 확인한다.
- 링크가 없으면 이 세션의 Drive 검색 도구로 후보를 찾되 이름만으로 소유자·대상을 확정하지 않는다.
  동명이거나 여러 사람의 문서이면 대상만 묻고 근거 정리는 계속한다.
- 기존 문서는 제목만 보지 말고 실제 탭·표·작성란·서식·편집 제한을 읽는다.
- 작성자·서명·확인자·실험 날짜·공식 승인 상태를 추측해 채우지 않는다. 여러 작성자에게 같은 본문·서명을 복제하지 않는다.

## 근거 범위

- 어느 저장소·폴더를 근거로 삼고 무엇이 보호 대상인지는 **프로젝트 `CLAUDE.md`를 따른다.** 워크스페이스 전체를 훑는 수집부터 돌리지 않는다.
- 커밋·작업보고·실험 기록·산출물을 근거로 쓴다. 기록이 없는 날의 작업을 전후 계획으로 추정하지 않고 미확인으로 두거나 사용자에게 묻는다.
- 호출 수·사용량·판정 결과·서비스 시험 같은 수치는 원본 기록으로 대조한다. 단위 시험 통과를 제품 완료나 연구 성과로 바꾸지 않는다.
- 프로젝트 폴더의 이전 노트·양식·렌더러는 보존하고 그 사용법은 프로젝트 지침을 따른다.

## 근거를 연구 내용으로

1. 근거 자료를 읽고 위치와 버전/해시를 기록한다.
2. 연구 질문·목적 → 방법과 비교 조건 → 관찰 결과 → 해석과 한계 → 후속 과제로 잇는다. 양식의 항목에 배치하고 양식에 없는 장을 일괄 추가하지 않는다.
3. 예상·실측·합성 fixture·mock·실제 제품 실행을 구분한다. 실패를 성공 실험으로 쓰지 않는다.
4. 실행 날짜와 문서 작성 날짜를 구분한다. 파일명·수정 시각만으로 수행일을 확정하지 않는다.
   월중 초안은 그 시점까지의 기록이다. 남은 기간의 활동을 미리 한 것처럼 쓰지 않는다.
5. 같은 실행을 인계·보고·로그에서 여러 번 봐도 한 번만 센다. 비용 보고값과 실제 청구, 자동 실행시간과 사람의 작업시간을 구분한다.
6. 근거가 없는 주장은 누락 이유와 확인할 것을 남긴다. 없는 자료를 채우려고 새 실험을 돌리지 않는다.

## Google Docs 반영

- 이 세션에 문서 읽기·쓰기 도구(커넥터)가 있는지 확인하고 그 도구의 편집 지침을 따른다. 없으면 그렇다고 보고하고 로컬 초안을 남긴다.
  로컬 파일을 만든 것을 Docs 반영 완료로 쓰지 않는다.
- 대상·양식·수정 범위가 확인되고 사용자가 작성을 요청했으면 그 범위에서 반영한다. 같은 승인을 다시 묻지 않는다.
- 템플릿 기반이면 구조·표·탭·서식을 보존하고 새 문서로 대체하지 않는다.
- 공유 권한 변경·서명은 작성과 별개다. 서명 이미지는 대상 작성자·확인자와 사용 지시를 확인하기 전에는 읽거나 넣지 않는다.
- 반영 후 문서를 다시 읽어 대상 월·누락·중복·수치·표·링크·서식 보존을 확인한다.

## 마무리

대상 문서 링크, 반영 범위, 근거, 미검증을 짧게 보고한다. 연구노트와 날짜별 작업보고(work-report)는 목적이 다른 산출물로 유지한다.
