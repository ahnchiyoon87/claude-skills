# 화면 검증 — 실제 화면에서 조작하고 상태로 판정한다

UI·화면 컴플레인·브라우저 동선을 검증하거나 고칠 때 읽는다. 브라우저 도구는 이 세션에서 쓸 수 있는 것을 쓴다(Playwright 등).

컴플레인은 증상이다. 대상 화면·사용자의 목적·문제를 재현할 입력·기대 상태를 현재 화면과 연결한다.
디자인 취향과 기능 결함을 구분하고, 승인된 이전 산출물이 있으면 그 기준을 먼저 확인한다.
작은 수정은 대표 동선까지 구현·검증한다. 디자인 방향이나 범위 확대의 판단이 필요하면 실제 전후 화면을 먼저 보인다.

## 안정적인 조작

- 버튼·탭·입력은 역할과 접근 가능한 이름, label, 안정적인 test id로 찾는다. 이름이 겹치면 해당 영역으로 범위를 좁힌다.
- `.first()`로 중복을 숨기지 않는다. 의도한 대상이 하나인지 확인한다.
- 대상의 준비 상태와 클릭 뒤 관찰할 상태를 확인한다. **클릭이 끝난 것은 업무 성공이 아니다.**
- 클릭·캡처 실패를 빈 catch로 삼키거나 실패 뒤 true를 반환하지 않는다. 실패한 단계와 실제 상태를 남긴다.
- 고정 sleep 대신 계약된 준비 상태·응답·표시 결과를 기다린다. 장기 연결이 있는 앱에서 networkidle을 준비 완료로 보지 않는다.
- `force` 클릭·임의 재시도·내부 store 직접 변경으로 사용자 동선의 실패를 통과시키지 않는다.
- 캔버스처럼 좌표가 필요한 곳은 현재 요소 경계·변환 상태에서 좌표를 구하고, 조작 뒤 선택·확대 상태를 확인한다.
  해상도·배율이 바뀌면 과거 절대좌표를 다시 쓰지 않는다. 캔버스 상태 주입은 진단이지 실제 조작 증거가 아니다.

## 작은 완결 시험

- 정상 동선 하나와 그 동선의 실패·빈값·비활성 상태를 확인한다. 관련 화면 크기에서 배치와 조작을 확인한다.
- 같은 계약을 쓰는 인접 화면·카드·상세·범례는 영향 범위에 넣는다. 새 UI 범위를 임의로 전수 확장하지는 않는다.
- 같은 의미는 모든 화면에서 같은 색·아이콘·용어·정렬을 쓰는지 본다. 한 컴포넌트를 바꾸면 그 의미를 표현하는 다른 자리도 본다.
- 화면·console/page error·실패 응답과 클릭 전후 상태를 남긴다. 스크린샷은 직접 열어 본다 — 사용자에게 대신 확인을 미루지 않는다.
- DB 값까지의 정확성은 실제 데이터 계보로 따로 확인한다(SKILL.md E10).
- mock 화면·합성 HTML 시험은 검사 방식의 증거이지 실제 제품 화면 검증이 아니다.
