# 인수인계 — 넘기기와 이어받기

- **넘기기**(1~10절) — 맥락 없는 새 세션·다른 사람이 이어받게 인계를 쓰거나 갱신한다.
  요청이 없어도 맥락이 잘릴 낌새가 보일 때, 작업이 일단락됐을 때, 방향이 정해졌을 때 쓴다.
- **이어받기**(11절) — 기존 인계를 실제 파일·git·실행 상태와 대조해 작업 상태를 복구한다.

인계 파일의 위치·이름, 결정 기록·질문 답·발화 대응표를 둘 곳, 먼저 읽을 도메인 문서(현재 상태 정본·제품 계약·
완료 판정)는 **프로젝트 `CLAUDE.md`를 따른다.** 인계는 그 정본들을 대신하지 않는다.
스크립트는 이 스킬 폴더(`~/.claude/skills/handoff/`)의 `scripts/`에 있다.

## 1. 수신자와 성공 조건

수신자는 이 대화를 한 줄도 못 봤고, 프로젝트 이력과 결정 이유를 모르고, 되물을 수 없는데 오늘 안에 일을 이어야 한다.
이 사람이 인계를 열고 **되묻지 않고, 끝난 조사를 반복하지 않고, 폐기된 방향으로 되돌아가지 않고** 곧바로
시작할 수 있어야 한다. "이게 뭐지?"라고 물을 곳이 하나라도 있으면 실패다.

## 2. 산출물 — 파일과 대사는 둘 다

| 산출물 | 형식 | 역할 |
|---|---|---|
| ① 인계 파일 | 정본 하나(기본 `HANDOFF.md`) | 본체. 배경·결정·규칙·실측·미결정 전부 |
| ② 대사 | 채팅에 코드펜스로 내는 실행 프롬프트(9절) | 열쇠. 새 세션 첫 메시지 |

파일만 있으면 수신자가 존재를 모르고, 대사만 있으면 채팅에 묻혀 다음 세션이 또 맥락을 잃는다.
부속(인계 §8에서 가리킨다): 사용자 발화 대응표(4절), 질문과 확정 답(8절), 결정 기록의 이번 항목(6절), 대역 시험 결과(10절).

## 3. 쓰기 전에 — 방금 확인한 증거로

인계의 "현재 상태"는 기억이 아니라 지금 다시 확인한 것으로 쓴다(헌법 §2). 다르면 실제 상태와 최신 사용자 발화가 이긴다.

1. 관련 **저장소마다** `git status`·`git log`·브랜치를 실행한다. 상위 폴더 하나가 단일 저장소라고 가정하지 않는다.
2. "수정했다"고 기억하는 파일은 열어서 내용을 본다. 실행 중 서비스·포트·컨테이너·백그라운드 작업도 실제로 본다.
3. 인계처럼 읽힐 다른 문서(두 번째 인계, 원본에서 딸려 온 README·TODO)가 있는지 찾는다.
4. 확인 못 한 것은 "미확인"으로 적는다.

그다음 답한다: 의뢰 출처와 마감 / 되돌리면 안 되는 결정과 이유 / 어기면 무효인 규칙 / 실측으로 닫힌 것(수치·출처) /
시도했다가 틀린 것 / 안 정해진 것과 무엇을 보면 정해지는지 / 외부에서 기다리는 것 / 열지 말아야 할 파일.
근거로 정할 수 있는 결정은 사용자에게 넘기지 않고 이유와 함께 적는다(바꿀 수 있다고 표시). 묻는 것은 근거가 없는 사실뿐이다.

## 4. 사용자 발화를 전부 뽑는다 — 가장 먼저

**인계는 사용자와 나눈 대화를 옮기는 일이다.** 기억·요약으로 쓰면 빠지고 바뀐다.
최근 것만 담고 초반 지시를 흘리는 것이 인계 실패의 최대 원인이다. 발화를 먼저 원문 그대로 모으고 그다음 정리한다.

```bash
PYTHONUTF8=1 python ~/.claude/skills/handoff/scripts/사용자발화추출.py <대화기록.jsonl> --출력 <대응표.md> [--이후 2026-09-29T06:00]
```

- 일반 메시지·작업 중 보낸 메시지·선택지 답·슬래시 명령 인자를 모은다. 맥락 압축 요약 안의 앞선 발화 목록도 따로 본다.
  기록 파일 위치는 프로젝트 `CLAUDE.md`, 없으면 `~/.claude/projects/<프로젝트>/<세션>.jsonl`. 기록이 없으면 대화 화면에서 옮긴다.
- 대응표 마지막 칸("인계 반영 위치")에 발화마다 반영된 인계 절을 적는다. **미대응 0이어야 끝난다.** 상태 질문("뭐 해?")은 "해당 없음".
- 같은 주제에서 발화가 바뀌었으면 최신이 앞의 것을 대체한다고 적는다(예: "경량화 최우선" → "현업 수준을 유지하며 경량화").
- 지적·교정은 요지와 그래서 바뀐 것을 반영한다. **"하지 말라"고 한 것은 인계 §3에 굵게.**
- 판단 기준이 되는 발화는 원문 그대로 질문 답 문서 맨 앞에 둔다. 해석은 원문 옆에 따로 붙인다.
- **에이전트가 제안만 하고 사용자가 받아들이지 않은 일은 할 일로 적지 않는다.** 동의인지 원문으로 본다
  (예: 조사를 제안했더니 "내가 골라야 하는 게 또 있냐고"라고 답했다면 동의가 아니다). 확정된 것을 다시 확인하는 단계를 끼우지 않는다.

## 5. 인계 파일 틀 — 이 순서, 절마다 역할 하나

"인계 §N"은 아래 틀의 절, "N절"은 이 스킬의 절이다.

```markdown
# HANDOFF — <프로젝트/작업 이름>

최종 갱신 <YYYY-MM-DD HH:MM> · 작성 <누가/무엇이>
**이 파일은 재개용 기록이다. 현재 사용자 지시·현행 계약·실제 상태와 대조하고, 다르면 그쪽이 이긴다.**

## 0. 30초 브리핑
<무엇이고 어디까지 왔는지 5줄 이내>

## 1. 배경과 목표
<의뢰·요구의 출처, 마감·범위·대상. 완료 판정 기준(DoD)은 사용자 원문 표현을 살린다>

## 2. 확정된 방향 — 바꾸지 마라
<항목마다 "왜" 한 줄. 이유가 없으면 수신자가 좋은 뜻으로 뒤집는다>

## 3. 절대 규칙 — 어기면 산출물이 무효다
<어겼는지 판정 가능하게("품질 유지" 금지). 사용자가 금지한 것은 굵게. 보호 대상(WIP·원본·잠긴 파일)>

## 4. 확정 사실 — 다시 조사하지 마라
<저장소별 경로·브랜치·미커밋 변경과 의미, 실행 중 서비스, 마지막 성공 검증의 명령·결과, 확인 시각.
 실측값은 수치 + 방법 + 측정일 + 출처>

## 5. 폐기된 판단 — 되살리지 마라
<한 줄에 하나: 무엇을 — 왜. 경위는 결정 기록>

## 6. 미결정 — 무엇을 보고 정하나
<안 정한 것과 원인 미상 이상 동작. 각각 무엇을 측정·확인하면 정해지는지. 후보를 정답처럼 쓰지 않는다>

## 7. 외부 대기 — 우리가 못 정하는 것
<누구에게 무엇을 기다리는지>

## 8. 자산 지도 — 무엇이 어디 있고 언제 여는가
<파일별 역할과 "언제 여는가". 결정 기록·질문 답·대응표 위치. 열지 말 것, 인계처럼 보이는 다른 문서의 지위>

## 9. 다음 행동 — 순서대로
<번호 순. 항목마다 무엇을·어느 파일에서·어떤 명령으로·선행 조건·완료 판정. 외부 대기에 안 막히는 것을 앞에>

## 10. 갱신 규칙
<7절 표를 옮긴다>
```

- 내용이 없는 절도 지우지 말고 "해당 없음" 한 줄. 절이 없으면 다음 갱신 때 아무 데나 쓴다. 빈 절을 채우려고 지어내지 않는다.
- "이전에·아까·그 파일·방금" 같은 이 세션에서만 통하는 말은 절대 날짜·절대 경로·구체 이름으로 바꾼다.

## 6. 이력과 충돌 — 현재 사실만, 한 곳에

인계 정본에는 **현재 사실·규칙·상태·다음 행동**과 **폐기 한 줄씩**만 둔다. 경위·진행 서사·해소된 실패의 상세는
프로젝트의 결정 기록(`DECISIONS.md` 등, 위치는 프로젝트 `CLAUDE.md`. 없으면 인계 옆에 하나 만든다)에 둔다.

| 무엇 | 인계 | 결정 기록 |
|---|---|---|
| 지금 참인 사실·결정·규칙 | §2·§3·§4 | — |
| 폐기된 판단·기각된 접근 | §5에 한 줄 | 근거·증거 |
| 해소된 실패·되돌린 변경·잘못 짚은 원인 | 재발 방지 "하지 말 것"만 §3 또는 §5에 한 줄 | 전량 |
| 미해소 실패·원인 미상 | §6 | 경위 |
| 지적받고 다시 한 것 | 바뀐 규칙·방향만 §2·§3 | 지적 원문과 경위 |

결정 기록 항목은 **무엇을 시도했나 + 어떻게 실패했나(오류 원문) + 해소/미해소/원인 미상**. 사소하거나 창피하다고
빼면 새 세션이 같은 실패를 반복한다. 판단에 영향 없는 입력 오타·중간 로그만 뺀다.

인계가 실패하는 흔한 원인은 정보 부족이 아니라 **모순**이다.
- 같은 사실을 두 곳에 쓰지 않는다. 한 곳에 쓰고 나머지는 `→ 인계 §4`처럼 가리킨다.
- 확정(§2·§4) / 미확정(§6) / 외부 대기(§7)를 한 문장에 섞지 않는다.
- 폐기된 판단은 지우지 말고 한 줄 남긴다. 지우면 같은 추론으로 같은 결론에 다시 간다.
  예: "문서를 40종으로 늘리면 컨텍스트 초과" — 실측 40종이 38,000토큰이라 그냥 들어가므로 기각.
- 수치에는 출처와 측정일을 붙인다. "약 40명"이 아니라 "H100 80GB · Llama 3.1 8B 동시 40명에서 OOM(Red Hat 벤치마크, 2026-08 확인)".
  타 환경 벤치마크는 그렇다고 표시한다. 측정일은 사실의 일부이지 진행 서사가 아니다.

## 7. 갱신 — 해도 지저분해지지 않게

인계 파일은 **하나**다. `HANDOFF_2.md`·`HANDOFF_최신.md`를 만들지 않는다. 같은 작업의 인계가 있으면 그 파일을
현재 사실 기준으로 다시 쓴다(덧붙이지 않는다).

| 상황 | 고치는 곳 |
|---|---|
| 실측·조사가 끝남 | §4로 승격, §6에서 제거 |
| 방향이 결정됨 | §2에 추가 + 이유, §6에서 제거 |
| 시도가 틀린 것으로 밝혀짐 | §5에 한 줄, 경위는 결정 기록. §2·§4에서 제거 |
| 실패가 해소됨 | §6에서 제거. 재발 방지만 §3 또는 §5에 한 줄 |
| 외부 답변이 옴 | §7에서 제거하고 §2 또는 §4로 |
| 작업이 진행됨 | §9 순서 갱신, §4 스냅샷 재확인 |

- §1·§3이 바뀌면 작업의 전제가 흔들린 것이다. 사용자에게 보고한다.
- 끝난 일은 완료 목록으로 쌓지 말고 "이제 사실"로 §4에 올린다. 검증 안 된 것은 올리지 않는다.
- **길이**: §0은 5줄, 전체는 스크롤 3~4번 안. 넘으면 자주 바뀌거나 긴 것(측정 이력·후보 비교·상세 설계)을 밖으로 빼고 §8에서 가리킨다.
- **자립성**: §3 규칙이나 §9 완료 판정이 가리키는 것이 **안 바뀌고 짧으면**(계약 원문·산출물 이름·고정 단계 목록) 인계 안에 둔다.
  나쁜 예: §3에 "필수 항목 15개 누락 0"이라 쓰고 그 15개는 다른 파일에만 있다. 자립성이 분량보다 우선이다.

## 8. 질문과 확정 답, 동기화

- 사용자가 물은 질문과 지금의 확정 답·이유를 별도 문서(예: `QA.md`)로 남기고 인계 §9 첫 단계에서 읽게 한다.
  맨 앞에 4절의 기준 발화 원문을 둔다. 답이 바뀐 질문은 최종 답만, 대화 원문 위치(기록 파일·시각)를 함께 적는다.
- 기준·결정·용어가 바뀌면 그 말을 쓰는 문서(의뢰서·보고서·질문 답·결함 목록·설정 주석·기억 메모)를 검색해 같은 뜻으로 맞춘다.
  조사 원문·원자료는 고치지 않고 "원문의 이 판정은 옛 기준이며 지금은 인계 §N"이라는 안내를 인계에 둔다.

## 9. 대사 — 복붙용 실행 프롬프트

task-prompt의 [작업 지시 공통 계약](../task-prompt/references/intent-dod-context.md)을 적용한다. 제목은 task-prompt와 같다.
인계 파일이 세부의 정본이고, 대사에는 파일을 열기 전에 방향을 알 만큼의 의도와 핵심 DoD만 직접 적는다.

```text
의도(Why & Value)
<OO을 위해, ~~한다. 이어받을 작업의 최종 가치와 수혜자 — '인계한다'에서 멈추지 않는다.>

작업요령과 컨텍스트
<인계 파일 절대경로>를 읽고 현재 요청·실제 파일·저장소별 git 상태와 대조한다. 다르면 실제와 최신 사용자 지시가 이긴다.
<질문 답 문서 경로>를 먼저 읽는다. 확인된 근거는 재사용하고 바뀔 수 있는 상태만 다시 확인한다.
인계 §5의 폐기된 판단을 되살리지 않는다. 시작은 인계 §9의 1번, 제외 범위는 <…>.
진행하며 인계를 갱신한다.

인수조건(DoD)
1. <남은 작업의 결과가 만족할 값·구성과 미달 조건. 판정 하나에 한 줄. 상세는 인계의 해당 절을 가리킨다>
```

상세 수치·변동 이력은 대사에 복제하지 않는다.

## 10. 검증 — 세어서 판정한다

인계를 처음부터 새 세션의 눈으로 다시 읽는다. §9의 1번을 지금 바로 시작할 수 있는가, 되물을 곳이 있는가,
§9의 할 일마다 사용자 발화나 동의한 제안이 근거인가, 규칙이 사용자 지시를 막고 있지 않은가
(예: 사용자가 시킨 정리를 인계가 "건드리지 않는다"로 막음). 그다음 센다.

| 세는 것 | 목표 |
|---|---|
| 파일과 대사 중 빠진 것 | 0 |
| 대응표의 미대응 발화 / 가리킨 절이 실제로 없거나 뜻이 다른 것 | 0 / 0 |
| 반영 안 된 사용자 지적·교정·금지 | 0 |
| 결정 기록에도 인계 §5·§6에도 없는 이번 세션의 실패·기각 (대화 초반까지 거슬러 본다) | 0 |
| 이 세션에서만 통하는 지시어 | 0 |
| §9 항목 중 경로·명령·완료 판정이 빠진 것 | 0 |
| 재확인 없이 현재 사실처럼 쓴 문장 / §2·§3·§4에 섞인 진행 서사 | 0 / 0 |
| §3 규칙 중 가리키는 내용이 파일 밖에만 있는 것 | 0 |
| 인계·질문 답에 적힌 경로 중 실제로 없는 것 | 0 |
| 대역 시험의 중요 문제 | 0 |

경로는 존재만 보지 말고 적힌 대로 쓰면 되는지 본다(예: 덧씌우기 파일이 없는 이미지를 가리킴, 설정이 바뀐 장비 값을 그대로 읽음).

**새 세션 대역 시험** — 이 대화를 모르는 새 에이전트에게 인계와 질문 답만 주고, 사용자가 실제로 물은 질문에 답하게 하고
문서를 감사하게 한다. 틀과 판정법은 [references/새세션시험.md](references/새세션시험.md). 답을 확정 답과 대조해
일치 수와 중요·사소 문제 수를 세고, 고친 뒤 같은 질문으로 다시 시험해 **중요 문제 0**까지 반복한다.
대역 시험은 실제 새 세션과 구분해 기록한다.

**원본 인계 묶음을 한 파일로 줄였을 때** — 규범("하지 마라")·범위 경계("우리 몫이 아니다")가 통째로 사라지기 쉽다
(실제로 원본 규범 126개 중 1개만 넘어온 적이 있다). 세어서 확인한다. 의미 검토와 대역 시험을 대신하지는 않는다.

```bash
PYTHONUTF8=1 python ~/.claude/skills/handoff/scripts/인계대조.py --원본 <폴더 또는 파일> [--원본 ...] --사본 <요약 인계 파일>
```

종료 코드 0 = 규범·범위 경계 수가 줄지 않음, 1 = 줄어듦(옮기거나 뺀 이유를 인계에 적는다), 2 = 입력 오류.

하나라도 0이 아니면 아직 인계가 아니다. 통과한 뒤 인계 경로, 대사, 숫자를 함께 보고한다
(예: "발화 162개 미대응 0, 질문 21개 중 21개 일치, 중요 문제 4 → 0").

## 11. 이어받기 — 인계를 읽고 상태를 복구한다

"이어서 해줘", "어디까지 했지", "새 세션에서 계속"에 쓴다. 모든 짧은 질문이나 새 작업의 선행 절차로 강제하지 않는다.

1. **대상** — 프로젝트와 인계 위치를 요청·현재 경로·프로젝트 `CLAUDE.md`에서 정한다. 찾은 경로가 다른 프로젝트 것이 아닌지 본다.
2. **읽기** — 프로젝트 `CLAUDE.md`, 인계, 인계가 지정한 현재 계약·질문 답. 전체 재개 감사가 아니면 무관한 프로젝트는 읽지 않는다.
3. **대조** — 파일·저장소별 git(브랜치·기존 변경)·실행 상태·잠긴 파일을 실제로 보고 인계와 다른 점을 정리한다.
   인계 날짜만으로 실제 파일이나 사용자 지시를 덮지 않는다. 끝난 일과 인계 §5의 폐기된 판단은 되살리지 않는다.
4. **진행** — 다음 작업과 완료 조건을 정하고 해당 스킬로 진행한다. **상태 확인 요청이면 확인된 상태와 미검증만 보고하고 끝낸다.**
5. 진행하면 인계를 7절 규칙으로 갱신한다.

맥락 압축 뒤에는 요약의 경로·완료 작업·미결을 출발점으로 쓰고, 바뀔 수 있는 상태만 다시 확인한다. 처음부터 다시 하지 않는다.

## 12. 하지 않는 것

- 현황 보고서 말투("~를 완료했습니다")로 쓰지 않는다. 수신자는 보고받는 사람이 아니라 일을 이어받는 사람이다.
- §9에 `- [ ]` 체크박스 TODO를 쓰지 않는다. 완료 이력을 쌓지 않는다.
- 요약을 이유로 사용자 지시를 빼거나 뭉뚱그리지 않는다. 디테일이 인계의 존재 이유다.
- 일반론·프로젝트 소개·소감을 넣지 않는다. 실패는 잡음이 아니다(6절).
- "최종·완벽·완료"라고 쓰지 않는다. 진행 중인 일을 넘기는 것이다.
- **인계만 요청받았으면** 작업 파일·원자료를 고치거나 지우지 않고, 커밋하거나 다음 작업에 착수하지 않는다.

끝난 일의 보고는 work-report, 인계 없이 새 세션에 줄 단독 실행 지시문·할 일 정리는 task-prompt가 맡는다.
