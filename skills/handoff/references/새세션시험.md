# 새 세션 대역 시험 — 프롬프트 틀

언제 쓰나: 인계를 마쳤다고 말하기 전(SKILL.md 10절). 이 대화를 모르는 새 에이전트에게 준다.
준비: 사용자가 이번 대화에서 **실제로 물은 질문**을 15~20개 고른다(답이 바뀐 질문, 여러 번 되물은 질문을 포함). 기대 답은 시험 대상에게 주지 않는다.

```
You are a brand-new session taking over a project. You have NO prior context.
STRICT: do not run containers or services; do not modify, create, or delete any file; do not use the web.
Do NOT open the conversation transcript.

Step 1. Read completely, in order: <정본 인계 경로>, <질문과 확정 답 경로>, <보고서 경로(있으면)>.
You may open other local files these documents point to.

Step 2. Answer each question as you would answer the project owner (Korean, plain, 2–4 sentences).
Cite the file and section for each answer. If the documents do not answer clearly, write "문서로 답할 수 없음" and why.
<질문 1~N>

Step 3. Audit all documents, each item with file + quote:
- contradictions (between or within documents)
- stale statements (old criteria, old decisions, references to deleted things)
- paths that do not exist (check them)
- history/narrative noise in the handoff (it should hold only current facts, rules, state, next steps,
  plus one line per discarded decision — what was dropped and why; detailed history belongs in the decision log)
- places where a new session would be confused or would have to guess

Return the answers with citations, the audit list, and a one-line verdict:
"새 세션이 바로 이어갈 수 있는가: 예/아니오 + 이유".
```

판정:
- 답마다 확정 답과 대조해 일치/불일치를 센다. "문서로 답할 수 없음"은 불일치로 센다.
- 감사 항목은 사실인지 확인한 뒤 중요·사소로 나눠 세고 고친다(거짓 감사는 제외 이유를 적는다).
- 고친 뒤 같은 질문으로 다시 시험해 수치가 줄었는지 본다. 남는 사소 항목은 인계 §6 미결로 적는다.
